# 모바일 페어링 — IP 선택과 Tailscale 접속

Status: ready-for-human
Date: 2026-09-07

## 확정된 요구

- PC에서 네트워크 IP를 선택할 수 있다.
- 사용자는 Tailscale을 통해 모바일에서 접속한다.
- QR 페어링으로 기존 PC 터미널의 출력을 보고 입력을 보낸다.

## 제안하는 첫 버전

설정에 `모바일 연결` 항목을 추가한다. 네트워크 어댑터 이름과 로컬 IP를 함께 표시하고 새로고침, 포트 입력, 서버 시작/중지, QR 표시, 주소 복사, 기기 승인/해제를 제공한다. 모바일은 별도 설치 없이 브라우저로 접속한다.

서버는 선택한 로컬 IP에만 바인딩한다. QR과 복사 주소는 실제 바인딩에 성공한 주소와 포트로 생성한다. Tailscale 어댑터를 식별할 수 있으면 우선 표시하되 IP 대역만으로 Tailscale이라고 단정하지 않는다. IPv4 및 전역/ULA IPv6를 지원하며 URL의 IPv6 주소는 대괄호로 감싼다. 첫 버전은 scope ID가 필요한 link-local IPv6를 목록에서 제외한다.

포트 기본값은 43123이며 변경 가능하다. 선택한 IP가 사라지거나 포트가 사용 중이면 원인을 표시하고 시작에 실패한다. 다른 인터페이스로 자동 전환하지 않는다. 서버 실행 중 주소 변경은 중지 후 다시 시작하는 흐름으로 처리한다.

## 연결 방식 비교

1. **선택 IP에 HTTP/WebSocket 서버 제공:** 이번 제안. Tailscale 경로에서 기기간 연결을 사용하며 사용자가 요청한 IP 선택과 직접 대응한다.
2. **Tailscale Serve로 HTTPS 제공:** HTTPS가 필요한 브라우저 기능 확장에 유리하지만 별도 Tailscale 설정과 호스트명 관리가 필요하다. 후속 범위로 둔다.
3. **자체 클라우드 중계:** 사용자 요구에 필요하지 않으며 서버 운영이 추가되므로 제외한다.

직접 IP 모드는 HTTP/WS를 사용하며 전송 보호는 Tailscale 경로에 의존한다. 일반 LAN IP 선택 시 앱 자체 TLS는 제공하지 않는다는 설명을 해당 설정에 표시한다. 모바일 카메라 앱으로 QR을 열며, 모바일 페이지는 secure context가 필요한 카메라 API나 service worker에 의존하지 않는다.

## 구조

`모바일 Vue/xterm 화면 → HTTP/WebSocket gateway → 전용 named-pipe client → winmuxd → 기존 PTY`

- gateway는 Tauri 데스크톱 프로세스에서 실행한다. 창을 트레이로 숨겨도 유지하고 앱 종료 시 중지한다.
- 모바일용 화면을 별도 Vite entry로 빌드하여 앱에 포함한다. 모바일 entry는 Tauri invoke를 호출하지 않는다.
- 인증된 모바일 연결마다 전용 daemon client를 사용하여 PC의 attach/detach 구독과 분리한다. 연결 종료 시 reader/event task와 pipe도 정리되도록 client 수명을 명시적으로 관리한다.
- 원격 프로토콜은 세션 목록, attach/detach, 출력, 입력, 종료 알림만 허용한다. daemon의 모든 Method를 그대로 노출하지 않는다.
- 현재 daemon 이름의 workspace 접두사를 활용해 세션을 구분한다. localStorage에만 존재하는 PC 레이아웃 동기화는 첫 범위에서 제외한다.
- 기존 ADR의 모바일 제외 결정은 이번 사용자 요청에 따라 터미널 원격 접근에 한해 후속 ADR로 갱신한다.

## 페어링과 수명

서버 기본 상태는 꺼짐이며 자동 시작하지 않는다. IP/포트 선택만 기존 persistence 규약으로 저장한다.

QR은 2분간 유효한 일회용 암호학적 난수 초대 토큰을 URL fragment에 담는다. 모바일은 fragment를 읽은 후 주소에서 제거하고 페어링 요청을 보낸다. PC와 모바일에 같은 확인 문자열을 표시하며 PC에서 승인해야 세션 API에 접근할 수 있다. 초대 토큰은 한 요청이 획득하면 재사용할 수 없고 거절/만료 시 재발급한다.

승인 후 기기별 난수 인증 토큰을 발급한다. 모바일은 현재 탭의 sessionStorage에 보관하고 WebSocket 연결 직후 인증 메시지로 전송한다. 인증 전에는 세션 정보나 출력을 보내지 않는다. 인증·페어링 토큰은 서버 메모리에만 유지하고 URL query나 로그에 기록하지 않는다. 기기 해제와 서버 중지는 해당 연결을 즉시 종료하고 토큰도 무효화한다. 앱 재시작 또는 서버 재시작 시 재페어링한다.

HTTP Origin/Host 및 WebSocket Origin을 실제 접속 주소와 대조한다. 요청 본문/메시지 크기, 미인증 연결 시간, 동시 연결 및 페어링 시도 횟수를 제한한다. 승인 요청 화면의 기기명은 원격 입력임을 전제로 길이 제한과 텍스트 렌더링을 적용한다.

## 모바일 동작

- 연결 상태, 세션 목록, 터미널, 입력창, Enter/Tab/Esc/Ctrl+C 보조키를 제공한다.
- 터미널은 PC의 cols/rows를 유지하며 모바일에서 스크롤한다. 모바일에서 ResizeSession을 보내지 않는다.
- 한글 조합 중 중복 입력을 방지하고 명시적 전송 동작을 제공한다.
- 연결이 끊기면 상태를 표시하고 입력을 비활성화한다. 전송 여부가 불명확한 입력은 자동 재전송하지 않는다.
- 재접속 시 유효한 인증으로 세션에 다시 attach하고 터미널을 초기화하여 scrollback을 복원한다.
- 출력 큐는 제한하며 느린 클라이언트/이벤트 유실 시 연결을 종료하고 재동기화하도록 한다. attach 시 snapshot과 live output 사이의 누락/중복 경쟁을 검증하고 필요하면 IPC 경계를 보완한다.

## 검증 기준

- IP 목록, IPv6 URL 생성, 주소 소실, 포트 충돌, 선택 인터페이스 바인딩을 확인한다.
- 승인 전 접근 거부, 초대 만료/재사용 거부, 잘못된 토큰/Origin 거부, 해제 직후 연결 종료를 테스트한다.
- 기존 세션의 출력/한글 입력/보조키/종료/재연결을 확인한다.
- 모바일 attach/detach가 PC 구독에 영향을 주지 않고 PC PTY 크기도 바꾸지 않는지 회귀 검증한다.
- 반복 접속/해제 후 task와 메모리가 누적되지 않는지 확인하고 느린 수신자의 출력 큐 상한을 검증한다.
- frontend build와 관련 Vitest/Rust 테스트를 실행한다. 가능한 환경에서 HTTP/WebSocket 통합 검증을 수행한다.
- 실제 휴대폰에서 Tailscale IP로 QR 접속하는 최종 검증은 해당 기기 접근 가능 여부에 따라 별도로 기록한다.

## 구현 상태

사용자가 서브에이전트 구현을 승인하여 첫 버전 구현을 완료했다. 자동 검증과 브라우저 검증 결과는 work/integration-report.md 및 work/verification.md에 기록한다. 실제 휴대폰의 Tailscale QR 접속과 키보드 입력 확인은 사용자 환경에서 남아 있다.
