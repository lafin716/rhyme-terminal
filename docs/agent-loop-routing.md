# 에이전트 루프 라우팅

일반 터미널과 분리된 Claude Code / Codex 계정 순환 실행 기능입니다.

## 사용

1. 설정의 **에이전트 루프**에서 참여할 프로필을 체크합니다. 시스템 계정과 새 프로필은 기본적으로 참여하지 않습니다.
2. 에이전트 순서와 각 에이전트 내 계정 순서를 정합니다. 단기·주간 사용률은 각각 기본 90%이며, 프로필의 빈 입력은 전역값을 따릅니다.
3. 메인 세션 생성 메뉴에서 **에이전트 루프 라우팅**을 선택합니다.
4. 순환 아이콘이 붙은 그룹 탭에서 작업합니다. 탭은 전환 후에도 유지되며, 이전 실행은 읽기 전용 기록으로 확인합니다.

기존 데몬을 실행한 상태에서 새 앱으로 업데이트하면 루프 기능은 사용할 수 없다는 안내가 나옵니다. 기존 작업을 마친 뒤 트레이 메뉴에서 종료하고 새 버전을 실행합니다. 앱은 실행 중인 기존 데몬을 강제로 교체하지 않으며, 이전 데몬에서도 일반 사용량 조회는 유지합니다.

## 전환 규칙

- 단기 또는 주간 사용량이 임계값에 도달하면 전환을 예약합니다. 표시용 출력 유휴 시간으로 종료를 판단하지 않습니다.
- 실행 중인 도구·하위 에이전트를 추적하고, 다음 실행을 막는 동기 hook 경계에서 이전 프로세스를 종료합니다. 실제 프로세스 종료를 확인한 뒤 새 PTY를 시작합니다.
- 같은 에이전트는 검증된 대화 ID와 해당 대화의 기록만 대상 프로필로 전달하여 재개합니다. 인증 파일이나 설정 폴더 전체를 복사하지 않습니다.
- 다른 에이전트는 사용자 요청·최근 대화·도구 결과·변경 파일·미확인 작업을 담은 정제된 인계 문서로 새 대화를 시작합니다. 숨겨진 추론·인증 객체는 인계 대상이 아닙니다.
- CLI에는 자동 계속 프롬프트를 시작 인자로 전달하지 않습니다. SessionStart의 대화 ID와 hook 준비 신호를 확인한 뒤 한 번만 입력하고, UserPromptSubmit으로 접수를 확인합니다. 확인되지 않은 프롬프트는 자동 재전송하지 않습니다.
- 완료된 요청, 사용자 질문, 승인 대기에 무조건 '계속'을 반복하지 않습니다.
- 다음 후보부터 순환 탐색하며, 상위 계정의 회복만으로 현재 작업을 옮기지 않습니다. 모든 후보가 소진되면 최신 사용량으로 회복을 확인할 때까지 기다립니다.
- 사용량을 확인하지 못한 후보는 한 번 실행할 수 있습니다. 확인 실패가 지속되면 보류합니다. 오래된 표본과 조회 오류를 사용률 0%로 취급하지 않습니다.

## 제어 및 복구

일시정지는 자동 라우팅과 사용자 입력을 잠그며, 실행 중인 명령을 즉시 강제 종료하는 버튼이 아닙니다. 안전한 경계 확인에 실패하거나 추적되지 않는 백그라운드 작업을 발견하면 자동 전환을 중단하고 기존 작업을 유지합니다. 이유가 그룹에 표시됩니다.

그룹 종료는 해당 그룹 실행을 종료하고 자동 재개도 취소합니다. 데몬 재시작으로 불확실해진 실행은 복구 대기로 남으며, 이전 작업이 중복 실행되지 않도록 자동 재생하지 않습니다.

## 구조

- src-tauri/src/loop_routing/: 설정·그룹 모델, SQLite 상태 저장, 데몬 런타임, CLI/대화 기록 어댑터.
- src-tauri/scripts/loop-routing-hook.ps1: 실행별 환경으로 식별되는 hook. 원자 파일로 정규화된 이벤트를 전달합니다.
- src/composables/useLoopRouting.ts: 설정과 그룹 조회·제어, 안정적인 loop:<uuid> 탭 연결.
- 데이터: %LOCALAPPDATA%\com.user.winmux\loop-routing\routing.sqlite3 및 그룹/실행별 hook·인계·scrollback 파일.
- 설정: winmux:loop-routing:v1. 프로필 환경변수는 기존 계정 설정에서 실행 시 결합하며 라우팅 저장소에는 중복 저장하지 않습니다.
- IPC: LoopRequest, AccountUsage. Tauri loop_request의 op는 configure, list, create, pause, resume, next, stop, move, rename, history, conversations입니다.
- 사용량 요청은 데몬에서 계정별 캐시·동시 요청 병합을 사용합니다. 네트워크 조회가 같은 IPC 연결의 터미널 입력을 막지 않도록 독립 처리합니다.

## 지원 범위와 검증

Windows native Claude/Codex 실행 파일과 UUID를 가진 JSONL 대화 기록을 지원합니다. 기록 형식이나 위치가 다르면 자동 변환을 추측하지 않고 복구 상태로 멈춥니다. 프로필의 최초 로그인·프로젝트 신뢰·Codex hook 신뢰 설정이 필요할 수 있습니다. 이를 자동 승인하거나 기존 권한 설정을 우회하지 않습니다.

회귀 테스트는 우선순위·임계값·미확인 사용량·복구·대화 ID 일치·동기 hook·병렬 도구·장기 이벤트 처리·환경변수 비저장·실제 테스트용 PTY 종료/이력 보존을 다룹니다. 설치된 Codex의 hook 설정 파싱 검사는 격리된 빈 프로필에서 인증 없이 수행합니다.

브라우저 QA는 mock Tauri 환경에서 설정→생성→전환→이력→일시정지와 탐색기/단축키 통합을 검증합니다. 실제 유료 계정 사이의 대화 재개와 Claude↔Codex 모델 응답은 이 검사만으로 검증되지 않습니다.

검증 명령:

~~~powershell
pnpm.cmd exec vitest run --maxWorkers=2
pnpm.cmd build
cargo test --manifest-path src-tauri/Cargo.toml --lib -- --test-threads=1
cargo test --manifest-path src-tauri/Cargo.toml --lib loop_routing -- --include-ignored --test-threads=1
cargo build --manifest-path src-tauri/Cargo.toml --bins
~~~
2026-09-09 초기 검증 결과: 프런트엔드 223개(2 workers), Rust 126개(include-ignored), Vue 및 Tauri debug 빌드가 통과했습니다. 기본 병렬도에서는 기존 import-heavy 테스트가 5초 제한을 초과해 워커 수를 제한했습니다. 별도 앱 식별자와 데몬으로 수행한 native smoke에서 창 생성, PTY 연결/resize, 종료 정리를 확인했습니다. native 화면 캡처는 제한 안내 화면을 반환하여 네이티브 시각/조작 검증의 근거로 사용하지 않습니다.

### 기존 대화 연결과 이름 변경

새 루프 메뉴는 생성 창만 엽니다. 사용자가 새 프롬프트를 입력하거나 현재 작업 폴더의 기존 대화를 직접 선택하고 시작 버튼을 눌러야 생성됩니다. 최근 대화를 자동 선택하거나 실행하지 않습니다. 기존 대화 목록에는 작업 내용, 에이전트, 계정, 최근 시간이 표시되며 검색할 수 있습니다. 내용 없는 시작 기록과 하위 에이전트 대화는 제외합니다. 선택한 대화는 생성 시 다시 검증하며 검증 실패 시 입력을 유지하고 오류를 표시합니다. 신규 프롬프트는 시작 훅 확인 후 한 번만 전달하며, 시작 실패나 재시작으로 같은 프롬프트를 자동 재전송하지 않습니다. 재개에서는 연결된 대화만 검증하며 없는 대화는 빈 CLI로 대체하지 않습니다. 요청 ID로 생성 재시도를 중복 처리하지 않습니다.

Claude는 `--permission-mode auto`, Codex는 `--approve-for-me`를 기본 실행 옵션으로 사용합니다. 일반 터미널의 기본 에이전트 실행에도 적용하며 명시적인 사용자 실행 명령은 유지합니다.

루프 탭 더블클릭 또는 탭/사이드바 우클릭의 이름 변경으로 명칭을 수정할 수 있습니다. 이름 변경은 그룹 ID, 실행 중인 PTY, 대화 연결을 유지하며 SQLite에 저장합니다.

명시적 생성 UI는 프런트엔드 226개, Rust 137개(설치된 Codex 검사는 1개 제외), Vue 빌드와 앱/데몬 빌드로 검증했습니다. 브라우저에서는 생성 창 열기만으로 실행하지 않음, 두 시작 방식, 검색, 직접 선택한 대화 ID, 오류 후 입력 보존, 취소, 390px 화면을 검사했습니다. 대화 목록과 생성 요청은 `capabilities.explicitStart` 확인 후에만 전송하여 구버전 데몬의 자동 대화 연결을 방지합니다.
