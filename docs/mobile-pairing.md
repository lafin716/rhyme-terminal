# 모바일 터미널 연결

## 접속 순서

1. PC와 휴대폰에서 Tailscale을 연결한다.
2. Rhyme Terminal 설정의 **모바일 연결**에서 Tailscale 어댑터의 IP를 선택한다.
3. 포트(기본값 `43123`)를 확인하고 서버를 시작한다.
4. 휴대폰 카메라로 QR을 스캔한다. 초대는 2분 동안 유효하다.
5. 휴대폰과 PC에 표시된 확인 문자열을 비교하고 PC에서 승인한다.
6. 모바일에서 세션을 선택하고 출력 또는 입력창을 사용한다.

접속 주소는 `http://선택한-IP:포트/` 형식이다. QR에는 일회용 초대가 포함되므로 페어링에는 QR의 전체 주소를 사용한다. 만료된 초대는 PC에서 새로 발급한다.

## Android 앱

Android 앱에는 자체 터미널이 없으며 원격 PC에 연결해야만 사용할 수 있다. 메인 화면은 저장된 **원격 연결** 목록이다.

- 목록이 비어 있으면 PC 초대 링크(QR 주소)를 붙여넣어 첫 연결을 추가한다. 연결하면 PC 주소가 목록에 저장되고 PC 모바일 화면으로 이동한다. 같은 PC를 다시 초대하면 기존 항목을 갱신한다.
- 각 항목은 이름·주소·마지막 연결 시각을 보이며 `연결`, `이름 변경`, `삭제`를 제공한다. 목록은 최근 연결 순이고 최대 50개까지 저장한다.
- 저장 항목의 `연결`은 초대 없이 PC로 이동한다. 같은 앱 실행 중 이미 승인된 기기 인증이 남아 있으면 바로 붙고, 앱이나 PC 모바일 서버를 다시 시작했다면 PC에서 새 초대를 발급해 `+ 새 PC`로 다시 연결한다.
- PC 화면 상단의 `연결 목록` 버튼(오류 화면에서도 표시)으로 언제든 목록으로 돌아온다. PC의 터미널 세션은 계속 실행된다.
- 앱에는 PC 주소와 이름만 저장된다(`winmux:mobile-remotes:v1`). 초대 코드와 기기 토큰은 저장하지 않는다.

## GUI 없이 CLI 서버만 실행

설치된 데스크톱 실행 파일에 `--server`를 붙이면 창과 트레이를 띄우지 않고 모바일 연결 서버만 실행한다.
IP는 해당 PC의 Tailscale/LAN 어댑터 주소를 사용한다.

```powershell
# Windows PowerShell: GUI 실행 파일도 종료할 때까지 기다리도록 파이프로 실행
& "C:\path\to\rhyme-terminal.exe" --server --bind 100.100.10.20 --port 43123 | Out-Host
```

```sh
# macOS에 설치된 앱
/Applications/rhyme-terminal.app/Contents/MacOS/rhyme-terminal --server --bind 100.100.10.20

# 소스에서 별도 CLI를 빌드한 경우 (Windows에서는 rhyme-terminal-cli.exe)
rhyme-terminal-cli serve --bind 100.100.10.20
```

`--bind`를 생략하면 Tailscale 이름을 가진 어댑터, 일반 네트워크, 루프백 순으로 IP를 선택한다.
선택한 주소는 시작할 때 출력된다. 다른 주소가 필요하면 `--bind`로 지정한다.
`0.0.0.0`/`::` 전체 인터페이스 바인딩은 지원하지 않는다. 포트 기본값은 `43123`이다.

1. 터미널에 표시되는 `http://IP:포트/#invite=...` 전체 링크를 Android 앱의 **+ 새 PC**에 붙여넣는다.
2. 모바일과 서버 터미널의 6자리 확인 코드를 비교한다.
3. 터미널이 안내하는 `approve <request-id>`를 입력한다. 승인 전에는 모바일에서 세션에 접근할 수 없다.
4. 모바일에서 세션을 선택해 사용한다. 기존 GUI와 같은 모바일 화면과 인증 방식을 사용하므로 앱 업데이트는 필요 없다.

CLI 서버 터미널 명령:

| 명령 | 동작 |
| --- | --- |
| `status` | 서버 주소, 현재 초대, 등록 기기 확인 |
| `invite` | 2분짜리 일회용 초대 재발급. 이전 초대 링크는 무효화 |
| `approve <request-id>` | 표시된 연결 요청 승인 |
| `reject <request-id>` | 연결 요청 거절 |
| `revoke <device-id>` | `status`에 표시된 기기의 인증 해제 및 연결 종료 |
| `help` | 명령 목록 표시 |
| `quit` 또는 Ctrl+C | 모바일 서버 종료. 입력 스트림이 닫혀도 종료 |

실행 중인 세션이 없으면 `w1.mobile` 터미널을 현재 폴더에서 자동 생성한다. 기존 세션이 있으면
그대로 공유한다. 새 세션은 기본 120×30 크기이며 PC의 기본 셸을 사용한다.
`--new-session`은 기존 세션이 있어도 세션을 하나 더 만든다. `--shell`, 반복 가능한
`--shell-arg`, `--cwd`를 지정해도 새 세션을 만든다. 이름이 겹치면 `w1.mobile-2`처럼 번호를 붙인다.

```powershell
rhyme-terminal-cli.exe serve --bind 100.100.10.20 --shell powershell.exe --cwd C:\work
```

`rhyme-terminal-cli serve --json`은 서버 상태·초대·승인 요청·오류를 한 줄씩 JSON으로 출력한다.
서버 터미널에서는 계속 위 명령으로 제어한다.

서버를 종료하면 연결과 기기 인증은 폐기되며, 다시 시작한 뒤에는 새 초대로 페어링한다.
PTY 데몬과 터미널 세션은 계속 실행되므로 진행 중인 작업은 유지된다. 세션은 GUI 또는 기존
`rhyme-terminal-cli` 명령으로 관리할 수 있다. 모바일 클라이언트가 세션을 생성하거나 종료하는 권한은 추가하지 않는다.

## 동작

PC 창을 닫아 트레이로 숨겨도 연결은 유지된다. GUI가 제공하는 모바일 서버는 앱을 완전히 종료하거나 서버를 중지하면 연결과 인증이 폐기된다. CLI 서버는 해당 CLI 프로세스가 실행되는 동안 유지된다. 다음 시작 시 다시 페어링한다. 개별 기기는 설정 또는 CLI의 `revoke` 명령으로 접근을 해제할 수 있다.

모바일은 PC와 동일한 터미널 크기를 사용한다. 좁은 화면에서는 스크롤하여 내용을 확인한다. 한글은 입력창에서 작성 후 전송할 수 있고 Enter, Tab, Esc, Ctrl+C 보조키를 제공한다. 연결 중단 중에는 입력을 보내지 않으며 이전 입력을 자동 재전송하지 않는다.

## 접속되지 않을 때

- PC에서 선택한 IP가 현재 네트워크 어댑터에 존재하는지 확인하고 IP 목록을 새로고침한다.
- 같은 포트를 다른 프로그램이 사용 중이면 다른 포트를 선택한 후 시작한다.
- 휴대폰의 Tailscale 연결과 해당 PC 접근 권한을 확인한다.
- Windows 방화벽과 tailnet 접근 정책에서 선택한 포트로 접근할 수 있는지 확인한다. Rhyme Terminal은 방화벽/접근 정책을 자동 변경하지 않는다.
- 서버를 다시 시작했으면 새 QR로 다시 페어링한다.

직접 IP 모드는 HTTP/WS이며 Tailscale 경로를 통한 사용을 전제로 한다. 일반 LAN IP를 선택하면 앱 자체 TLS는 제공되지 않는다.

## 이전 버전에서 업데이트한 경우

이전에 실행해 둔 winmuxd는 새 모바일 연결 방식을 지원하지 않을 수 있습니다. 모바일 연결에서 데몬 업데이트 오류가 나타나면 진행 중인 터미널 작업을 먼저 마친 뒤 이전 데몬을 종료하고 새 빌드로 다시 실행하세요. 창을 트레이로 숨기는 것만으로 데몬이 갱신되지는 않습니다.
